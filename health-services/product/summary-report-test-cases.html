 HTTP 200, status: successful. SummaryReports is an array with one object per active day, sorted ascending by date (yyyy-MM-dd). Each object carries all metric fields + stockConsumedMap. Positive
TC-02 Different tenant resolves to its own schema tenantId = "si", uuid = f16be3e1-... HTTP 200 with si-schema data only (different counts & product variants than os). Confirms {schema} resolution per tenant. Positive
TC-03 Third tenant works (multi-tenant) tenantId = "ke", uuid = 17b6f113-... HTTP 200, returns ke employee's days (e.g. 3 days) with correct per-day counts. Positive
TC-04 createdBy taken from token/user info, not body uuid in RequestInfo.userInfo only; no createdBy field sent Response createdBy equals the request userInfo.uuid; data belongs to that employee only. Positive
TC-05 childrenTreated honours status filter any tenant with project_task rows childrenTreated counts only tasks with status ADMINISTRATION_SUCCESS or VISITED; other statuses excluded (verify vs direct SQL). Positive
TC-06 stockConsumedMap only counts delivered tenant with task_resource rows stockConsumedMap = SUM(quantity) grouped by productVariantId, only where isDelivered = true; non-delivered excluded. Positive
TC-07 Day bucketing by campaign timezone records straddling midnight boundary Each record grouped into its Africa/Lagos calendar day; date strings are yyyy-MM-dd. Positive
TC-08 Soft-deleted records excluded tenant with isDeleted=true rows Rows with isDeleted = true are not counted in any metric. Positive
TC-09 Narrow date range filters correctly startDate/endDate covering a subset of days Only days whose createdTime falls within [startDate, endDate] appear; boundaries inclusive. Positive
TC-10 No data in range → empty array valid tenant/uuid, range with no records HTTP 200, status: successful, "SummaryReports": [] (not an error). Positive
